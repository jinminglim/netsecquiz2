0. Exam strategy

Format: MCQ and Multi-Select, 1% per question (about 17–18 questions), with partial marks for Multi-Select. Questions are scenario based: “A student set up the above network topology in the lab…”, followed by a topology drawing, a CLI configuration, and a question asking what works, what is logged, how many, or which commands are (NOT) needed. Almost every question is a lab situation, so know the labs’ topologies, addresses and expected results.

How Multi-Select is marked

Each option is marked independently (D2L “Correct Answers” scheme). In the Quiz 1 statistics, the IPSG question had 1 correct option out of 5, and the option-selection rates were 62% (correct), 47%, 34%, 40% and 40%. Score per option = 0.62, 0.53, 0.66, 0.60, 0.60, which averages to 0.60, exactly the “Average Grade 0.6/1” shown. The smurf question reproduces 0.57 the same way.
So: treat each option as a separate True/False statement. Tick it only if you believe it is more likely true than false. A wrong tick costs only 1/n of the mark.

A method for “will this ping or connection work?” questions

  1. Write down the real source and destination IP. A router or switch pinging without source uses its exit interface IP, not its loopback or VLAN IP.
  2. Walk hop by hop. At every interface ask: is there an inbound ACL where the packet enters, and an outbound ACL where it leaves?
  3. In each ACL: go top-down, first match wins, then implicit deny. Check protocol, source, destination and which side the port operator is on.
  4. Repeat for the reply. Routers are stateless: a ping fails if either the request or the reply is dropped.
  5. Router-originated packets skip that router’s own outbound ACL. Inbound ACLs also filter packets to the router (pings to it, OSPF hellos, SSH).
  6. On Firepower/ASA: which interface does the packet enter, and what are the security levels? Is there an ACL on the ingress interface? Is the packet a reply to an existing connection (stateful)? Is it ICMP, which is not inspected by default?
  7. VRF: which routing table does the packet use? AAA: is the server unreachable (ERROR) or did it reject (FAIL)?

1. Access Control Lists (Lab 2.1a, 2.1b, notes 2.1)

An ACL is a sequential list of ACEs (access control entries). Each ACE has an action (permit or deny) and a test condition:

  • Standard: matches the source IP only (Layer 3).
  • Extended: matches protocol, source IP, destination IP, and source/destination port (L3 + L4), plus ICMP type.
TypeNumbersNamedPlace it…Why
Standard1–99, 1300–1999ip access-list standard NAMEnear the destinationIt only knows the source. Near the source it blocks that source from everything (over-filtering).
Extended100–199, 2000–2699ip access-list extended NAMEnear the sourceIt can match the destination, so drop early and don’t waste bandwidth.

Processing rules and direction

  • ACEs are processed top to bottom. The first match wins and later ACEs are not checked. The order matters, so put more specific ACEs first.
  • Implicit deny any at the end. It is not shown and not counted in show access-lists; add an explicit deny any to see a match counter.
  • An ACL with only deny statements blocks everything, so add permit any / permit ip any any to allow the rest.
  • One ACL per interface, per direction, per protocol (IPv4/IPv6). A second ip access-group … in replaces the first.

Two classic traps from the notes 1. An inbound ACL also filters packets destined to the router itself: pings to its interface, OSPF hellos, SSH/Telnet to it. A standard ACL inbound on a routed link can kill the OSPF adjacency, and with it every route.
2. An outbound ACL does not filter packets originated by the router itself (its own pings, OSPF hellos, syslog, NTP). deny ip any any out still lets the router ping out, but forwarded traffic is dropped.

Syntax

Standard (numbered and named)

R1(config)# access-list 1 remark Allow DSW1 LANs        ! optional comment
R1(config)# access-list 1 permit 192.168.10.0 0.0.0.255 [log]
R1(config)# interface g1/0/24
R1(config-if)# ip access-group 1 in                      ! in | out

R1(config)# ip access-list standard BRANCH-OFFICE-POLICY
R1(config-std-nacl)# permit host 192.168.20.3
R1(config-std-nacl)# permit 192.168.40.0 0.0.0.255

Extended

R1(config)# access-list 100 permit protocol src src-wild [op port] dst dst-wild [op port] [icmp-type] [log] [time-range name]
DSW1(config)# access-list 100 permit tcp host 192.168.10.3 host 10.2.2.1 eq 22 log
DSW1(config)# access-list 100 permit tcp 192.168.10.0 0.0.0.255 any eq 443 log
R1(config)# access-list 110 permit icmp any 192.168.1.0 0.0.0.255 echo-reply   ! no 'eq' for ICMP
  • At minimum, an extended ACE needs protocol, source and destination. Protocols: ip (all), tcp, udp, icmp, ospf, …
  • Port operators: eq, neq, lt, gt, range a b. The operator belongs to the address it follows. tcp 10.1.1.0 0.0.0.255 eq www any matches source port 80, which is wrong for browsing.
  • Port names: www 80, ftp 21, telnet 23, smtp 25, domain 53, tftp 69 (UDP), ntp 123 (UDP), snmp 161 (UDP). Use numbers for the others (22, 443, …).
  • ICMP keywords: echo (type 8), echo-reply (0), unreachable (3), time-exceeded (11). There is no eq.
  • log produces %SEC-6-IPACCESSLOGP messages, which are severity 6. They won’t reach a syslog server set to logging trap 4.

Named ACLs, sequence numbers and editing

R1# show access-lists
Extended IP access list WEB-POLICY
    10 permit tcp 192.168.20.0 0.0.0.255 host 10.1.1.1 eq 443 (15 matches)
    20 permit tcp 192.168.20.0 0.0.0.255 209.165.200.224 0.0.0.31 eq 443
R1(config)# ip access-list extended WEB-POLICY
R1(config-ext-nacl)# no 20                       ! delete one line
R1(config-ext-nacl)# 15 permit icmp any any echo  ! insert between 10 and 20
R1(config-ext-nacl)# deny ip any any              ! no number → appended (last +10)
R1(config)# ip access-list resequence WEB-POLICY 100 5  ! start 100, step 5
R1# clear access-list counters
  • Newer IOS lets numbered ACLs be edited the same way (ip access-list extended 100), and sequence numbers are inserted automatically (10, 20, 30…).
  • Trap: no access-list 101 … in global mode deletes the entire numbered ACL. If an interface still references a deleted ACL, then depending on the IOS either everything passes or filtering continues.
  • Edits take effect immediately. You never need to re-apply ip access-group.
  • Verify with show access-lists [n|name] (ACEs and match counts) and show ip interface g1/0/24 (“Inbound access list is 1”, “Outgoing access list is not set”).

Time-based and object group-based ACLs

R1(config)# time-range OFFICE
R1(config-time-range)# periodic weekdays 8:00 to 18:00     ! or absolute start … end …
R1(config)# access-list 101 permit tcp any host 192.168.1.10 eq www time-range OFFICE
The time-range uses the router’s own clock. If show clock shows a leading * (not authoritative or not synced) or the wrong timezone, the ACE is active at the wrong times. Fix it with NTP plus clock timezone SGT 8. Outside the range the ACE is skipped, as if absent, and processing continues to the next ACE.
router(config)# object-group network Inside_Eng
router(config-network-group)# 10.0.0.0 /24
router(config)# object-group network Inside_Mktg
router(config-network-group)# host 10.0.1.1
router(config)# object-group network Inside_Networks
router(config-network-group)# group-object Inside_Eng      ! nesting
router(config-network-group)# group-object Inside_Mktg
router(config)# object-group service Host_Services
router(config-service-group)# tcp www
router(config-service-group)# tcp 443
router(config)# access-list 100 permit object-group Host_Services object-group Inside_Networks any

Format: permit object-group SERVICE object-group SRC DST. The protocol comes from the service group. User, ICMP-type and Security object groups exist only on ASA firewalls.

2. Cisco Firepower / ASA firewall (Lab 2.2)

Security levels and default policy

ciscoasa(config)# interface ethernet1/1
ciscoasa(config-if)# nameif outside                   ! level auto 0
ciscoasa(config-if)# security-level 0
ciscoasa(config-if)# ip address 23.1.2.3 255.255.255.0
ciscoasa(config)# interface ethernet1/3
ciscoasa(config-if)# nameif dmz
ciscoasa(config-if)# security-level 50                ! MUST set — otherwise 0
ciscoasa(config-if)# ip address 192.168.2.254 255.255.255.0
ciscoasa(config)# interface vlan 1
ciscoasa(config-if)# no nameif inside                 ! names must be unique; 'inside' pre-used by VLAN 1
ciscoasa(config)# object network obj_any
ciscoasa(config-network-object)# no nat (any,outside) dynamic interface   ! remove default PAT
  • Security levels run from 0 to 100. nameif inside defaults to 100; any other name defaults to 0.
  • Higher → lower: allowed by default, and return traffic is allowed statefully (the connection table, show conn).
  • Lower → higher: denied unless an ACL on the ingress interface permits it.
  • Same level: denied by default (needs same-security-traffic permit inter-interface).
  • The firewall is stateful. Packets of an existing connection are not re-checked against interface ACLs.
  • The default dynamic PAT on outside (nat (any,outside) dynamic interface) makes inside hosts appear as 23.1.2.3. The lab removes it.
  • On the Firepower 1010 factory config, E1/1 is outside and the other ports belong to VLAN 1 “inside”. That is why “inside” must first be removed from int vlan 1.
ciscoasa# show conn

ASA ACL traps • Apply it inbound on the interface where the traffic enters. To publish the DMZ server that is outside, not dmz.
• An inbound ACL replaces the default “permit to lower levels” for that interface. Putting permit … eq www inbound on inside stops inside users using SSH, HTTPS and DNS. Putting an ACL inbound on dmz stops the DMZ server from starting connections out.
• access-list … permit icmp any any inbound on outside, with no NAT, lets the Internet ping your inside hosts.

ICMP and MPF inspection

ICMP is not inspected by default. An inside → outside ping sends the echo request out (higher → lower), but the echo-reply arrives on a lower-level interface with no matching state and is dropped. Browsing works because TCP/UDP is stateful by default. Two fixes:

! Fix 1 (lab Part 4): make ICMP stateful via the default MPF policy
ciscoasa(config)# policy-map global_policy
ciscoasa(config-pmap)# class inspection_default
ciscoasa(config-pmap-c)# inspect icmp
! global_policy is already applied by default:  service-policy global_policy global

! Fix 2: stateless ACL letting the replies back in
ciscoasa(config)# access-list OUTSIDE extended permit icmp any any echo-reply
ciscoasa(config)# access-group OUTSIDE in interface outside

icmp permit any outside controls ICMP to the firewall’s own interface, not through it. Inspection does not override security levels for new traffic: outside → DMZ pings still need an ACL.

Modular Policy Framework (MPF)

An ACL used in match access-list only classifies; it doesn’t permit or deny. A service-policy has no in/out keyword, and an interface policy only affects traffic through that interface. There is only one global policy.

4. TCP SYN flooding attack and defence (Lab 2.5)

  • Normal handshake: SYN → SYN-ACK → ACK. After SYN-ACK the server holds a half-open / embryonic connection in the SYN-RECV state.
  • The attacker (a scapy script, sudo python tcpsynflood target-ip target-port) sends SYNs from spoofed sources and never ACKs. The backlog fills (the 512 default in the lab) and PC-A can’t connect.
  • If a spoofed IP is a live host, it replies RST and frees the slot, so attackers spoof unused addresses.
  • Lab setup: sudo systemctl start apache2 and sudo sysctl -w net.ipv4.tcp_syncookies=0. Disabling SYN cookies makes the server vulnerable for the demo; with cookies the server keeps no state until the ACK.
  • Monitor with ss -t -r state syn-recv | wc -l, which counts half-open connections.
ciscoasa(config)# access-list WEB extended permit tcp any host 192.168.2.100 eq www
ciscoasa(config)# class-map WEB-CLASS
ciscoasa(config-cmap)# match access-list WEB
ciscoasa(config)# policy-map WEB-POLICY
ciscoasa(config-pmap)# class WEB-CLASS
ciscoasa(config-pmap-c)# set connection embryonic-conn-max 50 per-client-embryonic-max 5
ciscoasa(config-pmap-c)# set connection timeout embryonic 0:00:10     ! optional: free half-open faster (default 30 s)
ciscoasa(config)# service-policy WEB-POLICY interface outside
ciscoasa# show service-policy interface outside
What happens with the limit in place Once the embryonic limit is reached, the firewall intercepts new SYNs. It answers SYN-ACK itself (with SYN cookies) and only opens a connection to the server once a real client completes the handshake. Spoofed SYNs never reach the server, the SYN-RECV count stays low, and PC-A can still browse.
Traps per-client-embryonic-max alone is useless against random spoofed sources, because every packet is a “new client”. The policy must be on an interface the attack actually crosses: outside, dmz, or global, not inside. Embryonic limits do nothing against Slowloris.

5. Slowloris attack and defence (Lab 2.6)

  • Low-rate DoS: a small amount of crafted traffic from a single PC can bring the server down.
  • It exploits HTTP: the server must receive the complete request header (ending in a blank line, \r\n\r\n) before responding, and the connection stays reserved meanwhile. Slowloris opens many connections and sends partial headers very slowly.
  • Its connections are established (the handshake completes), not embryonic, and they are not idle (a header line every ~10 s).
  • Tool: slowhttptest -c <connections> -u http://x.x.x.x (install via ICT-WIFI, then disable Wi-Fi!).
set connection …MeaningAgainst Slowloris (one attacker)

conn-max Nmax total connections for the classProtects the server, but the attacker fills all N, so legitimate users are still denied
embryonic-conn-max Nmax half-open connections (then TCP Intercept)No effect: connections are established

Lab 2.6 step 2.4: “slowhttptest wrongly says the service is unavailable” With per-client-max, slowhttptest’s own availability probe comes from the same attacker IP, which is already at its limit, so it is refused and reports service available: NO. Meanwhile PC-A browses normally. A distributed Slowloris (many bots, each under the per-client limit) would still need conn-max, timeouts or upstream protection.

6. Out-of-Band management, VRF, jump host and SSH (Lab 3.1)

  • In-band: management traffic flows over the same production LAN as user traffic. Convenient, but exposed to malicious users.
  • Out-of-band (OoB): a separate, dedicated management network with no user traffic, only reachable by network engineers and administrators.
  • Devices provide management ports next to the console port: Catalyst 9200L, 9300L and Firepower 1010 have one (Gi0/0 / Management1/1). The Catalyst 8200L has none, so it uses VRF (a management VRF).
  • Other OoB devices: a serial console server (remote access to console ports), KVM over IP (servers), and server BMC/IPMI.

Virtual Routing and Forwarding (VRF)

A VRF creates separate routing tables, so traffic in one table never crosses into another. It logically divides one router into several. Interfaces not in a VRF stay in the global table.

R1(config)# vrf definition OOB
R1(config-vrf)# address-family ipv4
R1(config)# interface g0/1/1
R1(config-if)# vrf forwarding OOB          ! FIRST — this REMOVES any existing IP address
R1(config-if)# ip address 172.16.99.1 255.255.255.0
R1# show ip route                     ! global table only — no OOB routes
R1# show ip route vrf OOB             ! OOB table
R1# ping vrf OOB 172.16.99.10          ! plain ping uses global table → fails
VRF traps Entering vrf forwarding after the IP address wipes the IP (“IPv4 disabled and address(es) removed”). A host on the production side cannot ping the VRF interface; that is the whole point (lab step 2.2). There is no routing between VRFs unless route leaking is configured.

Jump host (jump server / jump box)

  • An intermediary that is the entry point from a less-secure zone to a more-secure zone (the OoB LAN).
  • Pros: the attack surface shrinks to a single point of entry, which is easier to log, monitor and audit.
  • Cons: it is an attractive target and a single point of failure, so it must be securely hardened.
  • Typical design: a hardened Linux machine with SSH, in the DMZ, permitted to access the OoB LAN. It must not route between its two interfaces.
  • OpenSSH shortcut: ssh -J user@jumphost admin@device (ProxyJump).

After authentication, give users no more access than necessary. Two models: rights assigned directly to users (privilege levels), or rights assigned to roles that users get (RBAC with CLI views).

12. NTP (Lab 3.5)

Synchronised time is essential for correlating logs across devices and for time-based ACLs. NTP is defined in RFC 5905, runs over UDP 123, and has three modes: client/server, peer (symmetric) and broadcast.

Formulas (memorise these) Offset θ = [(T2 − T1) + (T3 − T4)] / 2. If positive, the client is behind and must move forward.
Round-trip delay δ = (T4 − T1) − (T3 − T2), i.e. total time minus the server’s processing time.
Worked examples 1. Notes: T1 10:00:00, T2 11:00:01, T3 11:00:02, T4 10:00:03 → θ = (1h 1s + 59m 59s)/2 = 1 h; δ = 3 s − 1 s = 2 s.
2. T1 10:00:00.000, T2 10:00:05.300, T3 10:00:05.400, T4 10:00:00.500 → θ = (5.3 + 4.9)/2 = +5.1 s; δ = 0.5 − 0.1 = 0.4 s.
3. T1 11:00:00.100, T2 .180, T3 .200, T4 .300 → θ = (0.08 − 0.10)/2 = −10 ms (client ahead); δ = 0.2 − 0.02 = 180 ms.
Timestamp fieldNTP requestNTP reply
OriginignoreT1

TransmitT1T3
Referencewhen the sender’s system clock was last updated (T4 is recorded locally by the client)

Stratum

  • Stratum = how many NTP hops from the authoritative source (stratum 0: atomic or GPS clock). Higher stratum means lower accuracy.
  • A device synchronised to stratum n becomes stratum n+1, and automatically acts as an NTP server for others. Stratum 16 means unsynchronised.
  • ntp master 5: the router uses its own clock as an authoritative source at stratum 5 (the default when no number is given is 8). Use it only if no reliable external source is reachable. Its clients become stratum 6.
  • NTP pool (e.g. 0.sg.pool.ntp.org) needs DNS: ip name-server 8.8.8.8. Enterprises sync hierarchically: edge router ← pool, then switches ← edge router.

Configuration and verification

R1# clock set 9:39:00 05 july 2013              ! privileged EXEC
R1(config)# clock timezone SGT 8
R1(config)# ntp master 5                           ! server using own clock
R2(config)# ntp server 10.1.1.1 [prefer]           ! client
S1(config)# ntp peer 172.16.0.2                    ! symmetric
R1(config-if)# ntp broadcast    /   S1(config-if)# ntp broadcast client   ! interface mode
R2# show ntp associations

Securing NTP

! server
R1(config)# ntp authentication-key 1 md5 NTP-pa55w0rd
R1(config)# ntp trusted-key 1
! client
S1(config)# ntp authentication-key 1 md5 NTP-pa55w0rd   ! same key (case-sensitive!)
S1(config)# ntp authenticate                              ! enforce authentication
S1(config)# ntp trusted-key 1
S1(config)# ntp server 10.0.0.1 key 1

The server attaches an MD5 digest computed with the pre-shared key; the client recomputes it and accepts the message only if they match. This protects against an attacker injecting false NTP replies.

14. Cisco Flexible NetFlow (Lab 3.6)

  • NetFlow keeps statistics about IP packets passing through a device in a NetFlow cache and exports them to a collector (e.g. ManageEngine NetFlow Analyzer). It exports no payload.
  • A flow is a unidirectional sequence of packets sharing the same key fields. Classic key fields (7): source IP, destination IP, source port, destination port, L3 protocol, ToS byte (DSCP), input interface.
  • Variants: Flexible NetFlow / v9 (RFC 3954), IPFIX (RFC 7011), the IETF standard based on v9, sFlow (RFC 3176) (sampling), and JFlow (Juniper).

The four configuration steps

! 1. flow record — match = KEY fields, collect = non-key statistics (or use predefined: netflow ipv4 original-input)
R1(config)# flow record my-record
R1(config-flow-record)# match ipv4 source address
R1(config-flow-record)# match ipv4 destination address
R1(config-flow-record)# match transport source-port
R1(config-flow-record)# match transport destination-port
R1(config-flow-record)# match ipv4 protocol
R1(config-flow-record)# match ipv4 tos
R1(config-flow-record)# match interface input
R1(config-flow-record)# collect counter bytes
R1(config-flow-record)# collect counter packets
! 2. flow exporter — where to send
R1(config)# flow exporter my-exporter
R1(config-flow-exporter)# destination 192.168.1.50
R1(config-flow-exporter)# transport udp 9999              ! must match the collector's port
R1(config-flow-exporter)# source lo0                      ! optional; default = exit interface IP
R1(config-flow-exporter)# export-protocol netflow-v9
! 3. flow monitor — record + exporter + cache
R1(config)# flow monitor my-monitor
R1(config-flow-monitor)# record my-record
R1(config-flow-monitor)# exporter my-exporter
R1(config-flow-monitor)# cache timeout active 30
! 4. apply to the interface
R1(config)# interface g0/0/1
R1(config-if)# ip flow monitor my-monitor input     ! and/or output
  • Verify with show flow record NAME, show flow exporter NAME, show flow monitor [NAME] [cache|statistics].
  • Active timeout exports long-lived flows periodically (default 1800 s; 30 s in the lab). Inactive timeout exports a flow once it has been idle for that time (15 s). The cache in the lab held 200,000 entries.
  • Wireshark on the collector: ip.src == 192.168.1.1 && udp.dstport == 9999 && !icmp. With source lo0, the source becomes 10.0.0.1.

Reading the cache

IPV4 SOURCE ADDRESS: 192.168.1.75      IPV4 DESTINATION ADDRESS: 10.0.0.1
TRNS SOURCE PORT: 0                    TRNS DESTINATION PORT: 2048
INTERFACE INPUT: Gi0/0/1   IP PROTOCOL: 1   counter bytes: 12024   counter packets: 8
  • Protocol 1 = ICMP, 6 = TCP, 17 = UDP.
  • For ICMP the “destination port” holds type × 256 + code: echo request (8,0) = 2048, echo-reply (0,0) = 0.
  • 12024 / 8 = 1503 bytes per packet = 1475 (ping -l) + 8 (ICMP) + 20 (IP).
Counting flows Count the distinct combinations of the key fields only. Per direction, monitor and interface: one ping session = 1 flow in, its replies = 1 flow out. Three TCP connections to port 80 from one PC = 3 flows with the 7-key record (different source ports), but 1 flow if the record only matches the destination address and port.

Security use: a SYN flood shows as huge numbers of tiny 1–2 packet flows to :80 from many sources. Slowloris shows as many long-lived, low-byte flows from one source. Smurf shows as an echo-reply flood toward the victim. Combine with syslog in a SIEM for correlation.

Top exam traps (read before the quiz)

  1. A standard ACL near the source over-filters. Place standard ACLs near the destination and extended ACLs near the source.
  2. The implicit deny is not counted. Add an explicit deny any to see matches.
  3. A router pinging without source uses its exit interface IP.
  4. An outbound ACL doesn’t filter router-originated traffic. An inbound ACL does filter traffic to the router, including OSPF hellos.
  5. A ping fails if the reply is blocked. Routers are stateless.
  6. eq port after the source means the source port.
  7. There is no eq for ICMP types.
  8. no access-list N … deletes the whole numbered ACL. Use ip access-list … / no 20.
  9. A second ip access-group … in replaces the first.
  10. Edits to an applied ACL take effect immediately.
  11. Time-based ACLs use the router clock, so you need NTP and the timezone.
  12. ASA ACLs use subnet masks and access-group NAME in interface IF.
  13. ASA: no ACL means security levels decide; an inbound ACL replaces “permit to lower” on that interface.
  14. ASA: ICMP is not inspected by default. Add inspect icmp in global_policy/inspection_default, or an echo-reply ACL.
  15. ASA: nameif other than “inside” means security level 0. Equal levels can’t talk by default.
  16. ASA: stateful, so return traffic of allowed connections is never checked against interface ACLs.
  17. write erase then reload: answer N to “Save?”.
  18. An ACL can’t stop a SYN flood or Slowloris aimed at a public server.
  19. SYN flood → embryonic-conn-max (TCP Intercept). Slowloris → per-client-max.
  20. per-client-embryonic-max doesn’t help against random spoofed sources. conn-max alone lets one attacker hog all slots.
  21. The service-policy must be on an interface the attack crosses. A class-map ACL only classifies.
  22. slowhttptest says “unavailable” because its own probe is limited, while PC-A works.
  23. vrf forwarding removes the IP address. Use ping vrf / show ip route vrf.
  24. access-class … in without vrf-also rejects VTY sessions from VRF interfaces.
  25. SSH needs a hostname plus a domain-name, RSA ≥ 768 bits (2048 recommended), login local and transport input ssh.
  26. Jump host: single entry point and easy auditing, but an attractive target and single point of failure. It must be hardened and must not route.
  27. BMC on the IPMI port at 10.0.0.1. Proxmox on LAN 1 at 10.0.0.10:8006. LAN 3 = eno5.
  28. Linux bridge: no IPs in the dialog; click Apply Configuration. Use netplan apply in the VM.
  29. AAA falls back on ERROR only, never on FAIL. Always end the list with local.
  30. The default method list covers console and VTY. A custom list must be applied with login authentication.
  31. TACACS.net listens on 127.0.0.1 by default. Fix it in tacplus.xml; clients go in clients.xml.
  32. FreeRADIUS silently ignores unknown clients (which counts as an ERROR, so fallback happens).
  33. Type 7 passwords are reversible. secret = MD5 (5); sha256 = 8; scrypt = 9.
  34. Quiet mode blocks all remote logins. The quiet-mode ACL lists the hosts that are still allowed.
  35. Moving a command up a privilege level removes it from the lower levels.
  36. Exec authorization (aaa authorization exec) is needed for server-assigned privilege levels or views.
  37. Views: always enable, exit, show parser. Superviews hold views, not commands. include-exclusive blocks other views.
  38. Command accounting is TACACS+ only. commands 15 logs only level-15 commands.
  39. NTP: θ = ((T2−T1)+(T3−T4))/2 and δ = (T4−T1)−(T3−T2). The client is one stratum above its server.
  40. NTP auth keys are case-sensitive. The client needs ntp authenticate + trusted-key + server … key n.
  41. logging trap N sends 0..N. The SSH session needs terminal monitor. * on a timestamp means not synced.
  42. NetFlow flows are unidirectional and counted by key fields. ICMP echo = 2048. The exporter port must match the collector.
