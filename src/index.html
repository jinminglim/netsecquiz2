ACL: Access Control Lists

Lab 2.1a · 2.1b
In plain wordsAn ACL is a list of permit and deny rules that a router or Layer-3 switch checks against packets on one interface, in one direction (in or out).
Think of it likeA bouncer with a printed list. He reads from the top, and the first line that matches you decides. He stops reading there. If no line matches, you are refused, because there is an invisible “deny everyone” at the bottom.

The rules that decide every answer

  1. Read top → bottom. The first match wins and the rest are ignored.
  2. There is an invisible deny any at the end. It is not shown and not counted in show access-lists.
  3. Standard ACL (numbers 1–99, 1300–1999) checks the source IP only, so put it near the destination. Extended ACL (100–199, 2000–2699) checks protocol, source, destination and ports, so put it near the source.
  4. One ACL per interface, per direction. A second ip access-group … in replaces the first.
  5. IN = checked as packets arrive. This includes packets to the router itself (pings to it, OSPF hellos, SSH). OUT = checked as packets leave, but packets made by the router itself are NOT checked.
  6. Routers don’t remember conversations. A ping works only if the request and the reply both get through.

⚠ Traps

  • The invisible deny any exists and is never counted.
  • Standard near the destination, extended near the source.
  • A router or switch pinging with no source uses its exit interface IP, not its loopback or VLAN IP.
  • An inbound ACL also blocks traffic to the router (ping, OSPF, SSH). An outbound ACL never blocks the router’s own traffic.
  • A ping fails if the reply is blocked. Always trace both directions.
  • The port operator belongs to the address right before it (source or destination).
  • ICMP types use keywords with no eq: echo, echo-reply, unreachable.
  • A wildcard is not a subnet mask. Router ACL = wildcard; Firepower/ASA ACL = subnet mask.
  • Edits to an applied ACL work immediately, with no need to re-apply.
  • A router’s ACL deny sends an ICMP unreachable back (you see U), which can leak information to a scanner. Firepower/ASA drops silently.

Firepower / ASA firewall

Lab 2.2 (+ MPF in 2.5 / 2.6)
In plain wordsA stateful firewall. Each interface gets a name and a security level from 0 to 100. Traffic may go from a higher level to a lower level by itself, and the replies come back automatically because the firewall remembers the conversation. Going from lower to higher is blocked unless an ACL allows it.
Think of it likeA building. Inside = 100 is the staff floor, DMZ = 50 is the lobby, and outside = 0 is the street. Staff can walk down to the lobby or the street and come back, because the guard remembers them. Strangers from the street can’t come up unless their name is on the guard’s list (ACL). Pings are special: by default the guard doesn’t remember ping-ers, so the reply coming back up is treated as a stranger and blocked.

The rules

  1. nameif inside → level 100 automatically. Any other name → 0 unless you type security-level.
  2. Higher → lower: allowed. Lower → higher: blocked (unless ACL). Same level: blocked.
  3. Stateful: replies to allowed connections come back automatically. ACLs only check new connections.
  4. ICMP is not inspected by default, so ping replies are treated as new packets and usually dropped. Fix: inspect icmp, or an ACL permitting echo-reply.
  5. Apply the ACL inbound on the interface where the traffic enters: access-group NAME in interface outside. ASA ACLs use subnet masks.
  6. Putting an ACL on an interface replaces “higher → lower is free” for traffic entering that interface.
  7. MPF: class-map = which traffic, policy-map = what to do, service-policy = where (an interface or global).

TCP SYN flooding: attack & defence
Lab 2.5




In plain wordsA TCP connection starts with a 3-step handshake: SYN → SYN-ACK → ACK. The attacker sends thousands of SYNs from fake (spoofed) source IPs. The server answers each one and waits for the final ACK, which never comes. Each waiting slot is a half-open (“embryonic”) connection, shown as SYN-RECV. When all slots are full (512 in the lab), real users can’t connect.


Think of it likePrank phone bookings at a restaurant. Someone calls 512 times with fake names, and the restaurant holds a table for each one while waiting for confirmation. Real customers are turned away. The firewall fix (TCP Intercept) is a receptionist who answers the phone first and only passes on callers who actually reply.









Words you must know


WordMeaning


Half-open / embryonic / SYN-RECVThe server got the SYN and sent a SYN-ACK, and is still waiting for the ACK.


BacklogThe queue of half-open connections (512 in the lab). When it is full, new users are refused.


SYN cookies (on the server)The server stores nothing until a valid ACK arrives. The lab turns them off so the attack works.


embryonic-conn-max N (on the firewall)Once N half-open connections exist, the firewall does TCP Intercept: it answers SYNs itself and only connects real clients to the server.


Volumetric attackAn attack that floods with a huge amount of traffic. The notes call Smurf and SYN flood volumetric.

Slowloris: attack & defence
Lab 2.6




In plain wordsThe attacker opens hundreds of normal, fully connected TCP sessions to the web server and sends each HTTP request header extremely slowly, one line every ~10 s, never finishing it. The server keeps every connection reserved while it waits for the end of the header. When all slots are used, real users are refused. One laptop is enough: it is a low-rate attack.


Think of it likeCustomers who take every table in a restaurant and order one word every 10 seconds, never finishing their order. The fix is “max 20 tables per customer” (per-client-max).

AAA Part 1: Authentication

In plain wordsAAA = Authentication (who are you?), Authorization (what may you do?) and Accounting (what did you do?). Authentication can use a shared line password (weak), local usernames on each device, or a central AAA server (TACACS+ or RADIUS) that stores everyone’s login once.


Think of it likeAuthentication = showing your ID at the door. Authorization = which rooms your keycard opens. Accounting = the CCTV and logbook.


ERROR vs FAIL: the rule behind every fallback question
The device tries the methods in the order listed, e.g. group tacacs+ group radius local.

• ERROR = the server is dead or unreachable (no answer, timeout, wrong IP, not listening). → Try the next method.

• FAIL = the server answered “NO” (unknown user or wrong password). → Stop. You’re rejected. The next methods are never tried.

Analogy: if the security desk’s phone line is dead, you call the next desk. If the desk answers “you’re not on our list”, you don’t get to ask another desk.






The rules


    

  1. The default method list applies automatically to the console and VTY lines.
    2. 

  2. A named list does nothing until applied: line vty 0 15 → login authentication MY-LIST.
    3. 

  3. Always end with local. Without it, if all servers are down, nobody can log in, not even on the console.
    4. 

  4. The switch’s key must match the server’s shared secret, and the switch must be a listed client on the server.
    5. 

  5. Server-based AAA benefits: scalability/manageability (users configured once) and fault tolerance (several servers).
    6.

NTP: time synchronisation
Lab 3.5




In plain wordsNTP makes every device’s clock agree, so log timestamps line up and time-based ACLs fire at the right time. It runs over UDP 123. Stratum = how many hops a clock is from the master time source (stratum 0 = an atomic or GPS clock). Each hop adds 1, and accuracy gets worse.


Think of it likeEveryone setting their watch from the school clock, which was set from the national time signal. A watch set from another watch is one step (stratum) further away.







The two formulas
Offset θ = [(T2 − T1) + (T3 − T4)] / 2
Positive θ = the client is behind, so it moves forward. Negative θ = it is ahead.


Delay δ = (T4 − T1) − (T3 − T2)
= total round-trip time minus the server’s “thinking time”.


Example: (5.3 + 4.9) / 2 = +5.1 s; δ = 0.5 − 0.1 = 0.4 s.






The rules


    

  1. ntp master 5 = “I am a stratum-5 source using my own clock” (default 8 if no number). Use it only when no reliable outside source exists.
    2. 

  2. A client of a stratum-n server becomes stratum n+1, and then automatically serves time to others.
    3. 

  3. Modes: client/server (ntp server), peer (ntp peer, they sync each other), broadcast (ntp broadcast / ntp broadcast client, configured on an interface).
    4. 

  4. Authentication protects against fake NTP replies: an MD5 digest made with a shared key. Keys are case-sensitive.
    5. 

  5. Using a pool hostname (0.sg.pool.ntp.org) needs DNS: ip name-server 8.8.8.8.
    6.

Flexible NetFlow
Lab 3.6




In plain wordsNetFlow keeps statistics about traffic passing through a router, such as who talked to whom, on which ports, how many packets and bytes, and when. It stores them in a cache and exports them to a collector. It never stores the content. A flow = packets going one way that share the same key fields.


Think of it likeA phone bill: it lists every call (who, to whom, when, how long) but not what was said. Each direction of a call is a separate line on the bill.







7 classic key fields


Source IP · Destination IP · Source port · Destination port · L3 protocol · ToS (DSCP) · Input interface. A different value in any key field = a new flow.


4 configuration steps


  1. flow record: match = key fields, collect = counters
  2. flow exporter: where to send (IP, UDP port, v9)
  3. flow monitor: record + exporter + cache timeouts
  4. apply to the interface: ip flow monitor NAME input|output






R1(config)# flow record CCNP8-CUSTOM-OUT
R1(config-flow-record)# match ipv4 destination address           ! key
R1(config-flow-record)# match transport destination-port         ! key
R1(config-flow-record)# collect counter bytes                    ! statistic
R1(config-flow-record)# collect counter packets
R1(config)# flow exporter CCNP8-COLLECTOR-HOST
R1(config-flow-exporter)# destination 192.168.1.50
R1(config-flow-exporter)# export-protocol netflow-v9
R1(config-flow-exporter)# transport udp 9999                     ! must match the collector's port
R1(config)# flow monitor CCNP8-INBOUND-MONITOR
R1(config-flow-monitor)# record netflow ipv4 original-input      ! predefined 7-key record
R1(config-flow-monitor)# exporter CCNP8-COLLECTOR-HOST
R1(config-flow-monitor)# cache timeout active 30
R1(config)# interface g0/0/1
R1(config-if)# ip flow monitor CCNP8-INBOUND-MONITOR input
